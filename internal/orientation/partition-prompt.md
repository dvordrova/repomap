# Finish one orientation decision from complete context

The observations are model interpretations of supplied records. Their explicit
`supports` select original native source refs; `supporting_records` select the
full original values in `native_support`. `basis` retains the originating layer,
never promotes earlier model prose into native proof. The complete source
inventory remains provenance outside these choices. Empty local signals do not
establish global absence or comprehensive semantic coverage.
`citation_sources` gives closed original facts (a*) or target-qualified seeds
(tN.nN), native kind, exact target ownership and original evidence. Select the
particular source AND its actual supporting value for every claim or command.
A seed header's name is not evidence of an effect; inspect the complete ordered
call/evidence use when present. An interpretation or uncertain signal without
native support cannot establish a native effect or launch requirement.
Do not cite a provenance union or guess support from a kind or name alone.
An included manifest source's evidence `path` identifies the invocation's root
makefile while `anchor` identifies its defining included source. Use the root
manifest's invocation directory, not the included source's directory, for cwd.
Use this evidence to distinguish launch facts from exports and another target’s
evidence; an interpretation never promotes an export to an entrypoint.

Final citation `refs` and `summary_refs` choose only the advertised
`citation_sources` refs (a* facts or tN.nN seeds). The d* context `basis`
and s* `supporting_records` refs are not final citation choices. Do not copy
record objects or source values into citation fields.

Refs go only in citation/target fields, never prose. Use readable English and
one sentence per prose value. Return only the requested fields; no guessing,
no preliminary votes, no invented commands or execution order.
Cite sources that support the particular claim or command. Complete contextual
coverage does not require citing every source again in every final decision.

`reader_gaps` describes required signal decisions that were refused. Its
original addresses are diagnostic provenance, not supporting choices or a
repaired claim. Accepted neighbouring signals remain useful, but do not present
a recipe or effect as exhaustively established when a relevant interpretation
is unavailable. Keep uncertainty explicit and omit unsupported steps.
