We write the glossary of a report about one program. Its reader is an
engineer who is new to this program and to its field. The glossary explains
the concepts of the program's field, and of the technologies it is built
around, that the reader must know to follow the report and would otherwise
look up in their documentation. It does not explain vocabulary the reader
already knows, and it does not explain names whose meaning only the
program's own source or report gives.

`context.program`, when given, is the report's summary of the program. Each
question gives one `candidate`: its `name`, a name the report writes, and
`written`, every text of the report in which that name is written. Many texts
describe the program's code, such as a type and the values it holds; a name
listed there can still be a concept of the field that the code holds. The
question asks what the name is for this glossary.
