# Decision: Repomap v3.3 Overnight Product Harness

Status: Approved by the repository owner in the current implementation
session.

## Product outcome

Test whether the existing repository guide becomes materially easier to use
when a Reading Path builds a compact mental model before progressively
disclosing exact source. Repair route-aware navigation, present bounded
documentation as documentation, make Architecture interactions useful or
intentionally absent, investigate grounded operating completion signals, and
audit current numeric bounds empirically.

## Approved implementation scope

1. Preserve immutable v3.2 Fuego, restic, and repomap baselines and compare the
   current code-first Reading Path with a dev-only progressive prototype built
   from the same saved report data.
2. Implement only the clearly better generic presentation using the existing
   report renderer and data model. Do not create a second production frontend
   or new repository-wide analyzer.
3. Render bounded README/document sections as readable documentation by
   default while preserving exact path/range provenance and raw-source access.
4. Add a presentation-level Reading Path overview from existing validated
   Brief, Study, target-user-job, and exact-anchor fields. It may organize
   learning but cannot claim runtime order or create repository facts.
5. Add route-aware scroll behavior: new workspace/path routes start at the top;
   same-path disclosure preserves context; native Back/Forward restoration is
   retained; drawers do not jump the page.
6. Compare a compact Architecture inspector with an area workspace. Publish
   only grounded joins to source, Study, Operate, or canonical Deep Dives;
   low-information nodes remain highlight-only or open exact source.
7. Investigate typed Paved expected-result/readiness fields only where exact
   repository evidence exists. Never execute target commands or invent output.
8. Inventory and instrument important hard and soft bounds, then widen only a
   measured binding default with a plausible product symptom. Preserve path,
   secret, confinement, timeout, and response-size safety.
9. Reuse saved reports wherever possible, cap fresh model work at 30 calls (12
   for limit experiments), and save exact request/response/resource metadata.

## Truth boundary

Local extraction, opaque IDs, exact source, authorization, validation, and
canonical Mechanism rules remain authoritative. Progressive presentation and
Architecture joins are projections over accepted data. A Reading Path is a
learning plan, not a runtime trace. Documentation supports purpose and usage,
not implementation behavior. Absence of completion evidence must remain
visible as absence, never editorially filled.

## Explicit non-goals

- No runtime-surface discovery, repository-wide SSA, global call graph, or
  points-to analysis.
- No target-repository command/test execution.
- No model provider, retry-loop, canonical Mechanism, or validator changes.
- No universal document engine, second renderer, new frontend framework, or
  repository-specific production rules.
- No combinatorial limit sweep or claim of globally optimal budgets.
- No commit or push for the overnight harness.

## Focused verification

- focused report projection, Study/Reading/Paved replay, and route tests;
- JS syntax and saved-report smoke checks;
- real desktop/mobile Fuego interactions plus restic and repomap regressions;
- `git diff --check`.

Slow runtime surfaces, external repository tests, full release checks, and a
new five-repository provider sweep are deliberately excluded.
