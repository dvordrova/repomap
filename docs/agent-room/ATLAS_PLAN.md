# Атлас: чтение репозитория таблицами

Предложение от 2026-09-04. Собрано по коду на ead56d70: пять карт подсистем, три независимых плана, три судьи, синтез с критикой. Не принято, пока владелец не сказал слово по разделу «Решения за владельцем».

## Суть решения

- Один слой чтения `internal/atlas` обходит репозиторий как места четырёх видов: каталог, файл, символ, граница. Он пишет один артефакт `atlas.json`, и страница читает только его.
- Над каталогами стоит уровень целей. Одна таблица портфеля: строка на цель, ячейки line и role. Роль ограничивает кандидатов стыков, фикстура с продуктом не стыкуется. Это первый экран портфеля и самый дешёвый слой.
- Модель получает таблицы. В строке один шаг контекста вверх и факты самого места, в ответе от одной до трёх коротких ячеек. Ключи строк выдаёт код, каждый ключ возвращается ровно один раз, закрытые списки и длины проверяет код.
- Смысл живёт в коде: членство, стрелки и их направление, стыки между целями, счётчики, идентификаторы, цвета зон, порядок колонок. Модель пишет заголовки и однострочники, переносит файл в соседний кубик, называет зоны и относит верхние кубики, выбирает ключевые символы, отвечает да или нет по стыку.
- Категоризация, группировка, сопоставление групп и groupindex удаляются одним переходом после того, как владелец посмотрел отчёт по атласу. Свёртка документации и ориентация остаются, ориентация переводится на кубики.
- Первый результат: печать таблиц без модели и живой прогон слоёв каталогов и файлов на repomap. Цена и время линейны по числу файлов, размер одного запроса от размера цели не зависит.

## Модель данных

Поля с пометкой `МОДЕЛЬ` пишет ответ таблицы. Всё остальное считает код.

```go
// internal/atlas/places. Только код. places.json в run dir владельца.
type Place struct {
    ID        string   // КОД. dir:<path> | file:<path> | sym:<path>:<line>:<name> | bnd:<path>:<line>
    Kind      string   // КОД. directory | file | symbol | boundary
    Path      string   // КОД. относительный путь; абсолютных путей нет нигде
    LineNo    int      // КОД. объявление или место вызова
    Depth     int      // КОД. каталог: глубина дерева. файл: раунд BFS по графу вызовов от объединения seeds всех целей, минимум по целям
    TargetIDs []string // КОД. цели-владельцы. одно место на путь, сколько бы целей его ни держало
    Given     string   // КОД. детерминированная строка. порядок запаса в разделе стадий
    Parent    string   // КОД. каталог родителя; для файла его каталог; для символа и границы файл
    Directory *DirectoryFacts // Readme, Doc, Dirs, Files, FileCount, TopBox bool
    File      *FileFacts      // Decls []Decl{Name, Kind, Signature, Doc, LineNo, Exported, FanIn}; Callers, Callees []string; Generated bool
    Symbol    *SymbolFacts    // Decl; Candidate bool
    Boundary  *BoundaryFacts  // Source fact|external_call; FactID, ObjectID; External; Method; Values; GivenKind; Direction in|out; Caller, CallerDoc
}
type Edge struct { From, To, Kind string; Count int; Witnesses []Witness } // КОД. рёбра файл к файлу: calls, imports, passes_callback, decorates, executes. Go добавляет импорты рабочих пакетов каталог к каталогу
type Witness struct { Caller, Callee, Path string; LineNo int }
type Graph struct { Version int; Revision string; Places []Place; Edges []Edge; Seeds []string; SHA256 string }

// internal/atlas. Единственный артефакт страницы. atlas.json в каждом run dir.
type Atlas struct {
    Version     int
    Repository  string       // КОД
    Revision    string       // КОД
    Targets     []Target     // КОД. по одной на каждую проанализированную цель любого языка
    Joints      []Joint      // КОД плюс МОДЕЛЬ. стыки между целями, уровень репозитория
    Budget      Budget       // КОД. Files, OpenAsked, DirsOpened, FilesOpened, RowsAsked по слоям
    Diagnostics []Diagnostic // КОД. итоги rejected.jsonl: Stage, Kind, Count, Samples
    SHA256      string
}
type Target struct {
    ID, Language, Kind, Name, Root string // КОД. ID равен programindex.Target.ID и facts.Target.ProgramTargetID
    Line       string      // МОДЕЛЬ. таблица портфеля; при одной цели строка корневого каталога
    Role       string      // МОДЕЛЬ. таблица портфеля: product | library | fixture | tool | example; запас: код по пути testdata, fixtures, examples
    Zones      []Zone
    Boxes      []Box
    Arrows     []Arrow
    Boundaries []Boundary
    Files, Symbols int     // КОД. знаменатели; страница ничего не пересчитывает
    Trace      []string    // КОД. ID кубиков от entrypoint вперёд по стрелкам, не больше восьми
}
type Zone struct {
    ID     string   // КОД. slug заголовка: цвет и якорь стабильны между прогонами
    Title  string   // МОДЕЛЬ. таблица имён зон
    Line   string   // МОДЕЛЬ. та же таблица
    BoxIDs []string // КОД. таблица отнесения плюс наследование вниз по дереву
}
type Box struct {
    ID     string // КОД. путь каталога; кубик, начатый моделью: путь плюс slug заголовка
    Dir    string // КОД
    Title  string // МОДЕЛЬ. ячейка title строки каталога; запас: имя каталога
    Line   string // МОДЕЛЬ. ячейка line строки каталога; запас: Given
    ZoneID string // КОД. верхний кубик из таблицы отнесения, остальные наследуют
    Side   string // КОД. in | mid | out по видам границ и entrypoint; заменяет lanes для порядка колонок
    Open   bool   // МОДЕЛЬ. ячейка open строки каталога; всегда true ниже порога бюджета
    Files  []File // КОД. файл ровно в одном кубике своей цели
    Keys   []Key  // КОД. символы с Key; не больше пяти на файл, страница показывает три на кубик
}
type File struct {
    Path    string
    Line    string   // МОДЕЛЬ. строка файла; запас: Given
    Open    bool     // МОДЕЛЬ. только в режиме бюджета; иначе true
    Asked   bool     // КОД. строка ходила к модели
    Symbols []Symbol // КОД. объявления function, method, type; Python и TS плюс переменные уровня модуля
    Callers, Callees int
}
type Symbol struct {
    ID        string // КОД. path:line:name. ориентация ссылается на него; facts.ObjectID переводится в него через Object.Location при сборке атласа
    Name      string // КОД. Go-метод как Receiver.Name; TS уже квалифицирован
    Kind, Signature, Doc string // КОД. Doc: первое предложение docstring по правилу двенадцати строк
    LineNo, Column int
    Line      string // МОДЕЛЬ. только для кандидатов; запас: Doc, иначе Signature
    Key       bool   // МОДЕЛЬ. ячейка key; без слоя символов ставит код по рангу
}
type Key struct { SymbolID, Name, Path, Doc string; LineNo int }
type Arrow struct {
    From, To  string    // КОД. ID кубиков, от вызывающего к вызываемому
    Calls     int       // КОД. различных мест вызова
    Witnesses []Witness // КОД. три самых частых пары символов
    Sentence  string    // МОДЕЛЬ. таблица стрелок; запас: from calls to: a, b, c
}
type Boundary struct {
    ID, BoxID, Path string; LineNo, Column int
    Caller    string   // КОД. охватывающий символ
    Direction string   // КОД. in | out
    Kind      string   // КОД для строк из facts; МОДЕЛЬ для SDK-вызовов. восемь видов
    External  string   // КОД. package.Receiver.Name
    Values    []string // КОД. литералы; шаблоны как /api/level/{param}
    Line      string   // МОДЕЛЬ. таблица границ; запас: External со значениями в Caller
    FactID    string   // КОД
}
type Joint struct {
    ID       string
    From, To Endpoint // КОД. из out-границы в in-границу
    Value    string   // КОД. общий литерал или метод с путём
    Same     bool     // МОДЕЛЬ. таблица стыков
    Label    string   // МОДЕЛЬ
    Possible bool     // КОД. совпадение через параметр пути или слепой выбор пира
    Blind    bool     // КОД. из таблицы пиров
}
type Endpoint struct { TargetID, BoundaryID string }
```

Правила артефакта: все ID уникальны и разрешаются, виды и направления из закрытых списков, пути относительные, текст без управляющих символов. Проверка при записи и при чтении, как у `facts.json`.

## Стадии

Одна стадия, одна таблица, один вид вопроса. Окно 40 строк, для символов 50. Раунды идут последовательно, окна одного раунда параллельно через общий исполнитель llm с четырьмя потоками. Колонка repomap считает прогон с `--target cmd/repomap`. Колонка kubernetes считает, что модель открывает 60 процентов каталогов и файлов; это прогноз до шага 5.

Общие правила таблиц.

- Ссылки строк локальны окну: r1..r40, d1..dN, b1..bN, p1..pN. Канонические 64-hex ID, абсолютные пути, run id и время в запрос не попадают.
- Состояние кубика для кэша: contract, sha промпта, sha запроса. Дайджест индекса в него не входит.
- Строки сортируются по пути, окна режутся по границам каталогов внутри раунда. Правка одного файла бьёт только его окна.
- Общие места нескольких целей: seeds это объединение seeds всех целей, Depth это минимальный раунд, вызывающие берутся из рёбер любой цели. Раунды идут по всему репозиторию, а не по цели, поэтому файл двух целей спрашивается один раз.
- Строка каталога несёт Given родителя, а не его модельную строку. Так правка README корня не переписывает дерево. Строка файла несёт модельную строку каталога, строки символа и границы модельную строку файла, строка стрелки строки обоих кубиков.
- Given в запрос не идёт, кроме Given родителя в строке каталога. Given это запас, а не подсказка, иначе модель его повторяет.
- В tables.md после живого прогона каждая строка печатается вместе: ключ, вход, Given, ячейки модели, источник. Владелец читает строки и ответы в одном файле.

Порядок запаса Given.

- Каталог: первая читаемая строка README; иначе первое предложение package doc для Go, docstring `__init__` для Python, description из package.json для JS и TS; иначе число файлов и первые три имени.
- Файл: docstring модуля для Python, ведущий JSDoc для TS; для Go package doc, если его несёт этот файл; иначе первый docstring файла; иначе число объявлений и первые три имени.
- Символ: первое предложение docstring; иначе сигнатура.
- Граница: external со значениями в вызывающем символе.

Отказ окна.

- DecodeValidate строг на всё окно: любая структурная или закрытосписочная ошибка отвергает окно, оно не кэшируется, его строки берут Given, сырой ответ и причина уходят в rejected.jsonl. Семантического повтора нет.
- Переполнение выходных токенов режет окно пополам. Это перераспаковка, не повтор.
- Для этого llm получает `ExecuteJSONEach`: тот же пул, тот же шлюз попыток, та же запись событий, но провал одного окна не отменяет соседей и возвращается в своём слоте. `ExecuteJSONBatch` и адаптивный пакет остаются: их вызывают классификатор README, портфель и свёртка документации.
- AGENTS про отказ всего пакета и запрет частичного результата правится тем же коммитом, что вводит `ExecuteJSONEach`. Побеждает правило конституции: проверка аннотирует и не прерывает прогон.

Режим бюджета.

- Включается, когда файлов больше порога. Тогда строки каталогов и файлов получают ячейку open, строки файлов делаются только в открытых каталогах, строки символов только в открытых файлах, предложения стрелок только между открытыми кубиками.
- Неоткрытые места получают Given, покрытие даёт код. Ниже порога ячейка open не спрашивается вовсе, открыто всё.

Режим без модели, флаг `--no-model`.

- Требует `--target`: портфель без модели не выбирается, а новую детерминированную выборку план не строит.
- Классификатор README не вызывается, роли пусты, как при отсутствии guidance-файлов.
- Свёртка документации не вызывается, reduced-documentation.json не пишется, обзор на странице это первая строка README корня из claims.
- Ориентация не вызывается. Главный поток даёт Trace атласа и факты entrypoint.
- Каждая ячейка атласа берёт Given, таблицы печатаются, атлас и отчёт строятся. Провайдер не нужен вовсе.

## Кубики, зоны, стрелки, ключевые символы, границы, стыки

- **Кубики.** Кубик по умолчанию равен каталогу с файлами цели. Каталог только с подкаталогами кубиком не становится. ID равен пути, Title из строки каталога с запасным именем каталога, Line из той же строки.
- Ячейка box строки файла переносит файл. Список кандидатов закрыт и мал: here, соседние каталоги под тем же родителем, кубики уже начатые под родителем, new с заголовком.
- Код применяет ответы после раунда: одинаковые заголовки под одним родителем сливаются в один кубик, новый заголовок с одним файлом отменяется, каталог с разными выборами делится по выбору, пустой кубик исчезает.
- Членство по файлу. Кубик границы, свёртка стрелок и ключи это один поиск по карте. Файл двух целей это одно место и одна строка, но по кубику в каждой цели.
- Side кубика считает код: in при http_server, queue_consumer или entrypoint, out при только исходящих границах, иначе mid. Это даёт порядок колонок слева направо без новых цветов и заменяет lanes.
- **Зоны.** Два кубика, как в договорённости. Первый: одно окно на цель предлагает want имён по крупнейшим верхним кубикам, want решает код. Второй: одна закрытосписочная ячейка на верхний кубик.
- Верхний кубик это первый каталог с кодом на пути от корня цели. Все кубики глубже наследуют зону ближайшего отнесённого предка. На kubernetes это держит отнесение в десятках окон, а не в сотнях.
- Zone.ID равен slug заголовка. Раскраска берёт этот slug, поэтому цвет и якорь не прыгают между прогонами, пока не изменилось имя. Сегодня цвет берётся из дайджеста состава и прыгает при любой правке.
- Первый экран не меняет алгоритм: блок на зону, до 5 кубиков в блоке, до 14 кубиков на экране, подпись про остальные на карточках. Цель с меньше чем четырьмя кубиками зон не спрашивает: каждый кубик сам себе зона с его заголовком.
- **Стрелки.** Свёртка файл к файлу из facts выносится в экспортируемую функцию и даёт рёбра calls, imports, passes_callback, decorates, executes со свидетелями. Для Go добавляются импорты рабочих пакетов из каталога зависимостей как рёбра каталог к каталогу, иначе файл, использующий только чужие типы, стрелки не имеет.
- Рёбра сворачиваются в пары кубиков одной цели по членству. Направление от вызывающего к вызываемому всегда, обе стороны могут дать две стрелки. Петли и межцелевые рёбра отбрасываются, межцелевые покрывают стыки. Calls равен числу свидетелей, Witnesses это три самых частых.
- Модель пишет только предложение при наведении, одна строка на нарисованную стрелку. Остальные стрелки получают строку кода из имён свидетелей. Свободного списка links больше нет, поэтому fold, collapseConnections и dropEcho нечего чинить. Карта рисует стрелки на уровне рамок как сегодня, стрелки внутри зоны говорит карточка.
- **Ключевые символы.** Код выбирает кандидатов файла: экспортируемые, документированные, затем по fan-in. Строка символа отвечает line и key. Код оставляет до 5 ключевых на файл, кубик показывает три первых: документированные, затем по fan-in.
- Без слоя символов ключи ставит код по тому же рангу, а строка символа равна его docstring. Фильтр имён с долларом уходит: кандидаты только из объявлений. Docstring едет вместе с символом, страница больше ничего не соединяет по строкам.
- **Границы.** Источники только кодовые: строки facts видов http_route, http_call, listen_address, config_read, dynamic_execution и отношения invokes_external к внешним символам пакетной авторитетности с хотя бы одним литеральным аргументом, плюс stdlib-список database/sql и net.Dial. Символы fmt, strings, errors никогда не строки.
- Kind даёт код там, где facts уже знают: http_route и listen_address это http_server, http_call это http_client, config_read это config, dynamic_execution это other. Модель классифицирует только SDK-вызовы. Direction всегда код: in для http_server и queue_consumer, out для остального.
- На карте граница это узел с пунктирной обводкой из существующего словаря chip-outside в последней колонке. Стрелка от кубика к границе для out и от границы к кубику для in идёт через тот же маршрутизатор. Наведение показывает строку, external и values. Клик открывает карточку с одним якорем на место вызова.
- Известный пробел остаётся: конкатенированные строки Go не видны facts, маршруты reportserver и его net.Listen границей не станут. Свёртка BinOp в surfacediscovery это отдельная работа.
- **Стыки.** Кандидатов строит код по всем границам всех целей. Для http совпадение метода и пути по сегментам с параметрами, как у порталов. Для очередей и sdk равный литерал с дырками шаблона как {param}. Пары config с config и db с db стыками не считаются: два сервиса с одной переменной окружения это не интеграция.
- Кандидаты стыков ограничены ролями целей: product с product и library, fixture только с fixture под тем же корнем фикстур, tool и example ни с кем. Роль даёт таблица портфеля, запас по пути. Список пиров слепой строки режется тем же правилом, поэтому сорок это верхняя граница, а не норма.
- Неоднозначность не отвергается. Один вызов против трёх маршрутов это три строки в одном окне, модель отвечает по каждой. На self-прогоне порталы дали ноль из-за этой неоднозначности, стыки её решают.
- Слепой случай: out-граница без кандидата получает одну строку с закрытым списком in-границ других целей и выбирает пира или none. Такой стык помечен Blind и Possible и рисуется пунктиром, как сегодня possible.
- Стыки лежат в atlas.json на уровне репозитория, как facts.json. Правило хранения в индексе цели-источника, ValidateSet и привязка группового графа исчезают. Карта репозитория и таблица интеграций на обзоре читают стыки. Порталы остаются в facts.json как факты, потому что приёмочная фикстура их закрепляет, но страница их больше не рисует.
- **Портфель.** Первый экран репозитория с несколькими целями группирует цели по роли: продукты и библиотеки развёрнуты со строкой и картой, фикстуры и примеры свёрнуты в одну строку с числом. На self-прогоне это карта cmd/repomap и строка про 20 фикстур в testdata.
- **Трасса.** Trace цели считает код: кубики entrypoint-фактов вперёд по стрелкам с наибольшим Calls, до восьми. facts.ObjectID переводится в Symbol.ID через Object.Location при сборке атласа. Шаги главного потока ориентации ссылаются на Symbol.ID и подсвечивают те же кубики через data-trace.

## Языки

- **Go.** Индекс не меняется. Файлы это различные пути объектов, объявления это function, method, type, метод показывается как Receiver.Name. Переменные-результаты вызова в строки не идут.
- claims начинает захватывать doc-комментарий `package` и блоки `type (`, чтобы строка каталога получала описание пакета. Регулярка README в claims заменяется белым списком расширений: сегодня internal/claims/readme.go считается README и теряет свои docstring.
- Рёбра: SSA-вызовы и passes_callback из индекса плюс импорты рабочих пакетов каталог к каталогу из каталога зависимостей. Границы: строки facts по net/http, os.Getenv, net.Listen, exec.Command плюс SDK-вызовы пакетной авторитетности с литералами.
- Генерированные файлы закрывает код и в строки не берёт: zz_generated, pb.go, маркер Code generated в первых 30 строках. Проверка по трём строкам не находит ни одного файла kubernetes, маркер идёт после лицензии.
- Тесты исключены как сегодня. Файлы, недостижимые по графу вызовов, идут последним раундом с контекстом каталога. dead_module для отсечения не используется, покрытие даёт дерево каталогов.
- **Python.** Индекс не меняется. Файл это объект модуля с Location на первой строке. Объявления это function, method, type плюс переменные, чей владелец модуль. self, локальные и лямбды в строки не идут.
- claims начинает захватывать docstring методов с отступом, сегодня только def и class в нулевой колонке. Рёбра: imports с from_import, calls, decorates. Границы: маршруты декораторов через facts, requests и httpx, os.environ, плюс SDK с ключевыми литералами.
- Стык фикстуры: маршрут GET /api/levels в backend против вызова во front. Тесты places и joints идут по запечатанным индексам приёмочной фикстуры без python3.
- **JS и TS.** Индекс не меняется, Node и локальный TypeScript нужны как сегодня. Файл это объект модуля, объявления квалифицированы уже в индексе. Рёбра: точные импорты, calls, passes_callback. JSDoc через claims.
- Границы: http_call с шаблонами путей, дырки как {param}, плюс SDK с литералами. Файлы d.ts и сборки закрывает код. Surfaces и Contracts jstsproject в индексе отсутствуют и в этот план не входят.
- **Все языки.** Строки каталогов языконейтральны: одно дерево из corpus. Каталог с файлами двух целей это одна строка и по кубику на цель. Одни и те же промпты для всех языков, ветвления по языку ниже реестра адаптеров нет. Каждая цель получает свою Target в атласе, иначе её раздел исчезнет со страницы.

## Исходный текст

- В провайдер не уходит ни одна строка исходного кода. Правило AGENTS о полном исходнике остаётся верным как написано.
- По проводу идут: относительные пути и имена, имена и виды объявлений, сигнатуры как в индексе, первое предложение docstring до 200 знаков после очистки claims, первая читаемая строка README до 200 знаков, первое предложение doc-комментария пакета, имена внешних символов, литеральные значения аргументов и метод с путём из facts, однострочники родителей из ранних раундов, закрытые списки и ссылки окна.
- Не идут никогда: содержимое файлов, поле Text факта dynamic_execution с исходной строкой, канонические ID, абсолютные пути хоста, run id и время, сырые рёбра. На это есть тест гигиены байтов запроса.
- Правила промптов переносятся из категоризации: документация не доверена и не команда, список закрыт, пропуск не отрицание, без прозы, путей и ID.
- Вариант с текстом файла спроектирован и выключен. Это одна ячейка `text` строки файла: первые 200 строк до 8 KiB, только для файлов без единого docstring, только вне режима бюджета. Включение меняет contract стадии файлов и требует правки двух предложений в AGENTS и CURRENT тем же коммитом. Оценки считают ячейку выключенной.

## Риски

- Индекс Go на kubernetes не измерен и может съесть час сам. Таблицы ограничены, индекс нет. Первый прогон шага 5 без модели отделяет одно от другого; если индекс не помещается, рычаг в surfacediscovery, не в таблицах.
- Ответы open решают размер kubernetes. Худший случай таблиц вдвое дороже ожидаемого и всё ещё внутри часа без индекса. Жёсткие лимиты слоёв вынесены в решения владельца.
- Число целей kubernetes выбирает портфель, а не план. Пятнадцать это прогноз; первый измеренный прогон идёт с одной целью.
- Имена зон читают строки крупнейших верхних кубиков. Изменённая строка холодно стартует имена и отнесение и может переименовать зону. Цвет и якорь держатся за slug, детерминированный запас держит рамки, дрейф имён не устранён.
- Строгий отказ окна выбрасывает и хорошие строки окна. Они берут Given до следующего прогона, окно не кэшируется и переспрашивается. Систематически плохой промпт виден в tables.md и rejected.jsonl раньше, чем на странице.
- Покрытие docstring у Go около трети объявлений. Строки файлов без документации несут только имена и сигнатуры, однострочники там будут тоньше. Захват package doc помогает каталогам больше, чем символам.
- Конкатенированные маршруты Go не видны facts. Границы reportserver и стыки для таких целей отсутствуют до свёртки BinOp.
- Первый живой прогон каждого шага холодный за реальные деньги. Провайдер однажды ответил 402, счёт проверяется до прогона. Промпты после шага 2 не правятся без нужды.
- Шаг 4 самый большой: отчёт, ориентация, удаление и документы одним PR. Тестовый каркас обычного пути живёт в том же коммите, иначе переход проверяется только живыми прогонами.
- Формат 76 и манифест 41 делают старые run dir нечитаемыми новой сборкой. Пути совместимости нет и сегодня.
- Слой символов самый крупный на kubernetes и спорит с предложением конституции про агрегаты. Он вынесен в отдельный шаг и решение владельца.
- Фикстура JS и TS не компилируется, TS проверяется по запечатанным артефактам приёмочной фикстуры и живым прогоном на репозитории владельца.
- Добавленный файл сдвигает окна своего раунда после себя. Ведомость по строкам это второй кэш вне слоя llm, она не строится.
- `--no-model` без `--target` не работает, потому что портфель без модели не выбирается. Детерминированная выборка всех кандидатов это новая логика, план её не строит.

## Решения за владельцем

- Текст файла по проводу: по умолчанию нет, только docstring и объявления; ячейка text включается отдельным решением с правкой AGENTS и CURRENT.
- Предложение конституции про агрегаты: по умолчанию правится одним словом в шаге 4, потому что строки символов и ключи от модели это договорённость владельца из brief, которая новее этого предложения. Если владелец скажет иначе, шаг 3 пропускается и ключи ставит код.
- Порог режима бюджета по числу файлов: по умолчанию две тысячи, ниже открыто всё и open не спрашивается.
- Жёсткие лимиты строк по слоям: по умолчанию нет, добавляются только если измерение kubernetes в шаге 5 выходит за час.
- Заголовок кубика: по умолчанию заголовок модели до четырёх слов с запасным именем каталога; альтернатива всегда имя каталога.
- Число зон на цель: по умолчанию от четырёх до восьми, корень из числа верхних кубиков.
- Порталы в facts.json: по умолчанию остаются как факты фикстуры, страница рисует только стыки; удаление требует правки expected.json и конституции.
- Параллельность таблиц: по умолчанию четыре, как у продукта; восемь возможно только для всего прогона целиком, потому что шлюз привязывается один раз.
- Имена флагов `--no-model` и `--atlas`: по умолчанию так, `--atlas` живёт до шага 4, `--no-model` требует `--target`.
- Фикстурные цели self-прогона: по умолчанию читаются как все, они доказывают стыки.
- Кандидатов символов на файл: по умолчанию десять, шесть в режиме бюджета; пиров в слепой строке до сорока.
- Первый прогон kubernetes: по умолчанию с `--target cmd/kube-apiserver`, чтобы час измерялся на одной карте.
- Роли целей: по умолчанию пять видов product, library, fixture, tool, example; стыки только между совместимыми ролями.
- Счёт провайдера пополнен до живого прогона шага 1.
