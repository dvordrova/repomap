## Persisted authority family

Four manifest-relative, hash-verified current files separate authority:

1. `study_investigation_facts.v1.json` — repository/Study/catalog/index binding,
   bounded card graphs, exact reading/node/edge restoration authority and sealed
   request batches; never the full index or source bodies.
2. `study_investigation_candidates.v1.json` — strict refs-only provider
   candidates bound to exact request bytes. Invalid raw output remains only in
   the redacted semantic journal/status accounting.
3. `study_investigation_result.v1.json` — one canonical final result per compiled
   card, rederived by replaying candidates through the current local validator;
   candidate array order cannot change its bytes.
4. `study_investigation_status.v1.json` — written last; closed state and bounded
   counts/digests only, with no raw provider/error prose.

All files use strict unknown-field rejection, canonical re-encoding, SHA-256,
mandatory credential scanning, and closed ceilings (facts 2 MiB, candidates
320 KiB, result 256 KiB, status 64 KiB). Facts bind the exact current
`study_themes`, Atlas Study catalog, repository revision/freshness, index
scenario/digest and every request digest. Absence or drift fails closed.

## Runtime and failure isolation

1. The stage runs only after current Study reduction/persistence and before the
   final post-provider repository reconciliation and report source-authorization
   pass.
2. Zero eligible batches configures no provider and writes a complete prepared
   family. A valid empty response is also a complete accepted outcome.
3. Invalid candidate siblings close item-locally. A whole invalid response,
   output limit, provider configuration/transport failure, or cancellation does
   not erase earlier valid batches; the current batch and untouched suffix stay
   prepared. Partial or failed mechanism enrichment makes an otherwise valid
   report DEGRADED, not unavailable HTML.
4. Secret scan, binding/integrity failure, unsafe persistence and repository
   freshness drift remain whole-run terminal. There is no semantic retry;
   shared transport may repeat only identical request bytes.
5. Provider accounting, semantic exchanges and console status use the closed
   `mechanism_study` stage. HTML receives no status codes, request refs, failed
   prose, or diagnostic frontier archaeology.
