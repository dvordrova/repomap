# Decision 199: Atlas-first Architecture and Study restoration

## Status

Approved by the repository owner in the current supervisory session after the
first live Decision 198 Casdoor run demonstrated a real product regression:
the exact local Atlas and Navigator worked, but the useful model-assisted
Architecture, Repository Brief and Study routes had disappeared.

Decision 198 remains the pushed rollback checkpoint at
`60c2f84fc683753f1f0c1a13b10ebb910f3bf3f9`.

## Outcome

An ordinary online Atlas-first run asks three independent, task-shaped model
questions:

1. Navigator selects one locally advertised startup action.
2. Architecture names and groups the existing bounded local component
   candidates.
3. Study produces one supported Repository Brief and bounded reading routes
   over the accepted Atlas/Architecture/source catalog.

The old raw-signal Orientation request, Guided Tour fan-out and per-direction
Study review fan-out remain outside ordinary execution. Local Atlas facts,
relations, source authority and canonical IDs remain backend owned.

## Architecture checkpoint

Reuse the existing `componentmap` synthesis and Apply contract. Its input is
rebuilt from the current `RepositoryGraph`, `ArchitectureGrounding`, Surface
roles and exact local witnesses after Navigator. FlowProof and an old
Orientation response are optional and absent in the Atlas-first path.

The model may only name, describe and group the existing advertised canonical
opaque member and anchor IDs. This reused provider shape is a parity bridge,
not yet the final short request-local-ref Architecture contract. It cannot
return relations, runtime order, evidence, paths or new members. Local Apply
preserves every structural fact and retains omitted members deterministically.

The requested report language is part of the exact prompt, cache and saved
record identity. English request bytes remain stable; Russian requests add one
narrow instruction that only model-authored names and descriptions use
Russian. The superseded whole-report localization stage is not restored.

Cancellation and typed resource exhaustion are terminal and publish no final
report. A transport-successful but semantically rejected Architecture response
is not cached or saved as an accepted synthesis and is never called a model
fallback. Its closed failed status and semantic journal remain; the separately
owned local Canvas may still be published explicitly as local data. There is
no retry or second Architecture call.

## Brief and Study checkpoint

Build one bounded Atlas-first Study catalog locally. Prefer accepted
Architecture component IDs and exact representative locations, add exact
Atlas startup evidence and available application Surfaces, then bounded exact
source anchors and documentation intent. Old `ProjectGuess`, raw Orientation,
source-signal arrays, raw graph/tree/edges, full source bodies and canonical
persistent IDs are not model-visible inputs.

One private request-local catalog assigns short typed refs to Units,
subsystems, components, Surfaces, exact reading targets, evidence and bounded
documentation claims. Canonical IDs and exact path/symbol/line values stay in
the private local catalog; the wire carries only short refs, semantic labels,
closed kinds/Authority and bounded facts. One combined provider response
contains:

- the five supported Repository Brief statements and optional domain terms;
- one to twelve editorial Study directions with three to five exact reading
  anchors each.

The response contains no catalog, version, hash or other backend-owned identity
token. It may copy only advertised short typed refs in fields of the matching
kind. Exact request/cache identity privately binds the response to the local
catalog. Backend resolution assigns canonical direction IDs,
rejects unknown/wrong-kind/duplicate refs, requires openable reading targets
and prohibits unsupported runtime-order prose. The product Shape is derived
locally from accepted Architecture refs cited by the result; the model does
not return a second grouping or relation set.
Invalid individual direction items may be omitted with bounded closed
diagnostics; the required Brief and at least one valid direction remain
fail-closed. There is no fuzzy repair, semantic retry or per-direction review
call.

The accepted result is persisted as versioned `atlas_study_request`,
`atlas_study_result` and `atlas_study_status` artifacts bound to the exact
Atlas, accepted Architecture, wire, private catalog, provider and language
identities. It projects into the existing ReportData/UI Study DTO so the
product regains its useful Brief and routes without a second visible Study
shape or any template change. The superseded `repository_study_map` producer
is not called by an ordinary Atlas-first run. Model prose uses the requested
report language directly. Search strings and reading order remain editorial,
not evidence or reachability claims.

## Ordinary sequence and publication

The online sequence in this first implementation is:

```text
local snapshot + Atlas
-> Navigator
-> Architecture
-> initial repository authority reconciliation
-> exact saved-source coverage
-> Atlas-backed Brief + Study
-> repository authority reconciliation after the external Study call
-> one authorized report/manifest publication
```

Navigator selection is optional context, not an input dependency of either
Architecture or Study. A library or monorepo with no startup recommendation
still receives the independently constructed Architecture and Study stages.
The observed three-call happy path is an implementation diagnostic, not a
permanent product ceiling.

Decision 177 remains authoritative for visible Architecture: a valid local
`ArchitectureCanvas` is always the canonical base map and is never called a
fallback. `ProposalAccepted` gates only model-authored grouping/enrichment and,
temporarily in this checkpoint, the Atlas Study request. An ordinary invalid
model proposal leaves the local Canvas visible. Existing terminal resource
semantics remain unchanged.

The reused Architecture provider contract is a parity bridge. It still exposes
the existing canonical opaque member/anchor IDs and `allowed_paths`; it is not
described as a new short-ref contract. Parity acceptance requires an
etcd-sized saved-response gate recording candidate/member/anchor cardinality,
request bytes, output tokens, complete response state, exact membership
acceptance and unchanged local relations. If that shape cannot complete
reliably, the next correction is request-local refs and/or sharding, never
fuzzy repair.

Offline runs make zero model calls and publish the local Atlas/Canvas. A
Navigator with no eligible local action remains truthfully `empty`; otherwise
provider-backed products are explicitly unavailable. No old semantic
artifact may silently satisfy a new request. Accepted records are bound by
their exact request/provider/language identities; the final report JSON/HTML
remain manifest-authorized.

## Acceptance

Provider-free saved-response tests must prove:

- online happy path records the current three calls in order and no old
  Orientation, Guided Tour, localization or review-fan-out call, without
  making that count a permanent product contract;
- accepted Architecture changes only conceptual grouping and preserves local
  members, relations and evidence;
- the canonical local Canvas remains visible when model enrichment is absent
  or rejected;
- a Navigator-empty library fixture still receives Architecture and Study;
- accepted Study yields a complete supported Brief and useful exact-source
  routes over the same accepted identities;
- one invalid Study route preserves the valid Brief and valid sibling routes;
- Russian prompt/cache/replay identity differs from English while schemas and
  closed labels remain stable;
- invalid typed refs, wrong-kind refs, duplicate refs and unsupported prose do
  not enter the canonical report;
- resource exhaustion at either new stage is terminal before report, manifest,
  latest, serve or open; and
- the saved Casdoor-shaped fixture is no poorer than the old product target:
  a non-generic model Architecture, a complete Brief and multiple distinct
  Study directions with openable source anchors.

After focused package and ordinary-run tests, build one exact candidate binary
for the owner. Direct Go tests/vet and real Casdoor/etcd artifact/JSON/UI checks
remain the final acceptance block; no shell harness is reintroduced.

## Non-goals

- no raw-signal Orientation compatibility branch;
- no model-computed graph traversal, edges, reachability or evidence;
- no new Atlas entity kinds solely to satisfy prose;
- no Guided Tour or per-direction review fan-out;
- no whole-report model localization;
- no retry, completion continuation, fuzzy repair, legacy reader or migration;
- no UI redesign in this decision.

The existing split/review Study machinery remains in the tree until an actual
etcd/library product comparison shows that the combined call is not a quality
regression.
