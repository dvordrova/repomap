# Decision 150: Small-library product corrections

## Status

Approved by the repository owner after fresh `--no-cache --lang ru` product
runs of `jackc/pglogrepl` and `tidwall/wal`.

## Observed failures

- A valid one-package library was rejected before architecture synthesis solely
  because the package landscape contained fewer than two packages.
- Study Brief validation required three shape areas even when the complete
  bounded repository bundle exposed fewer areas.
- Targeted research selected only the first source window for one file. A WAL
  durability question therefore saw `Close` and `cycle`, but not the distant
  `writeBatch` synchronization it attempted to describe, and published an
  unsupported absence claim.
- Architecture cards advertised exact anchors, surfaces, or paths while some
  cards had no inspector action. Accepted package-grounded synthesis was also
  labelled as rejected behavioral grounding.
- A library with two runnable examples was classified as an application because
  every build-selected `main` counted as a product entrypoint even though both
  executable roles were already exact `test_or_helper` roles.
- One optional Brief domain term without evidence support rejected the complete
  otherwise-supported Brief and prevented all subsequent Study editing.
- A source-reviewed LSN Study direction with four exact anchors was hidden by a
  post-publication lexical question-coverage heuristic, so the saved stage
  reported six selected directions while the user saw only five.
- A later uncached run returned useful candidate prose but shortened every
  opaque anchor hash to a distinguishing prefix. All eight candidates were
  rejected before source review as unknown IDs.
- The same rejected run silently rendered its remaining Overview while the
  failed Study outcome was visible only in terminal output.
- Two distinct related README documents were rendered as indistinguishable
  `README` actions in one otherwise accepted Study direction.

## Corrective contract

- A non-empty one-package `library_framework` bundle is eligible for the same
  bounded architecture synthesis as larger repositories. No runtime relation
  is invented.
- When every exact process entrypoint is an example/test-helper and a non-main
  package is build-selected, the repository remains a library. The example
  entrypoints remain visible secondary evidence rather than becoming the
  architectural head.
- Repository Shape contains one to seven exact supplied areas. Small
  repositories are not required to manufacture three conceptual areas.
- Targeted research may retain at most two distant bounded source windows per
  selected file, within the existing per-stage source-window, evidence, and
  byte ceilings. A lexical window cannot establish absence outside itself; the
  provider instruction states that boundary directly.
- Every visible non-diagnostic Architecture component opens a compact
  inspector when exact package or member context exists. Exact member
  locations are valid source actions even when Study did not select them, and
  an exact symbol location is preferred over a file-only location.
- In a served local report, exact source actions open the authorized repository
  target directly instead of preferring an embedded saved-source drawer.
- A one-step partial trace is an exact starting point, not a user-facing code
  path. User Architecture publishes only paths with at least two exact steps,
  and keeps published paths visible instead of hiding them in a dropdown.
- Russian output is repeated as an explicit contract in both provider messages;
  all explanatory prose is Russian while paths, identifiers, package names,
  and protocol/product terms remain unchanged. Locally derived fallback areas
  use the report language and an exact symbol rather than a humanized filename.
- Required Brief statements remain fail-closed. Invalid optional domain terms
  are reduced locally, so one editorial term cannot discard the supported Brief,
  Shape, and all later Study work.
- Question-term coverage remains diagnostic metadata. It does not suppress an
  accepted source-reviewed Study direction: natural-language wording,
  translations, and exact code tokens are not interchangeable relevance tests.
- A shortened bundle reference is restored only when its prefix is at least
  twelve bytes and uniquely identifies one supplied anchor, document, area, or
  mechanism. Exact IDs are unchanged; short, foreign, and ambiguous prefixes
  remain fail-closed.
- A rejected or failed model Architecture result is not published to the user as
  a package-based Architecture under the same product label. The deterministic
  projection remains available for diagnostics, but only accepted or normalized
  model grouping is eligible for the default Architecture tab.
- Product-stage failure must not be disguised as a successful substitute under
  the same name. Field-local reduction is allowed only for explicitly optional
  metadata and must preserve the accepted primary artifact.
- The bounded Study stage status is part of the product report. When Study does
  not publish, Overview remains available as an independent artifact but carries
  an explicit unavailable notice; it is never presented as a substitute Study.
- Related Study documents include their exact repository paths in action labels,
  so same-named files remain distinguishable without opening them.
- Study-to-Architecture return controls, map-context copy, and editor-open
  confirmations participate in the report-language UI layer.
- Package-grounded model synthesis is labelled as conceptual grouping, not as
  rejected behavioral grounding. Architecture inspector copy participates in
  the existing report-language translation layer.

## Acceptance

- focused tests cover one-package synthesis, one-area Study shape, distant
  source windows, the no-absence prompt boundary, source actions from exact
  component members, useful component inspectors, and honest canvas wording;
- fresh uncached Russian runs of `tidwall/wal` and `jackc/pglogrepl` complete;
- all resulting Architecture cards are clicked and inspected;
- full repository checks and the nearby etcd validation pass.
