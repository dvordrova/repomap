# Decision 198: Atlas-first product transition

## Status

Approved by the repository owner in the current supervisory session to finish
the current large iteration as a usable product. This decision builds on the
installed Decision 194 output contract, Decision 195 source coverage, Decision
196 Atlas/Navigator foundation, and completed Decision 197 cleanup.

## Outcome

An ordinary successful run opens one truthful Atlas-first workspace. Local
facts establish the repository anatomy; the first Navigator request selects an
exact, backend-owned next action over a resolved startup Surface-to-Operation
slice. The report shows that selection with its Authority and exact source
drawer. It does not preserve the old raw-signal Orientation call as a hidden
parallel path.

The iteration is complete only when the same pushed binary passes provider-free
repository checks, a real etcd artifact/UI/JSON inspection, and an owner-run
Casdoor gate. A live provider A/B remains owner-operated and happens last.
The owner receives an explicitly identified candidate PATH binary as soon as
the production cutover compiles. The complete test and product-QA block runs
after that installation so owner testing can proceed in parallel; only a green
acceptance block is committed, pushed and installed as the final exact binary.

## Product transition

### Replace the old Orientation call

The first Navigator question is fixed and product-owned:

> Which locally resolved application startup should a newcomer inspect first?

Seeds are every available application Surface participating in an exact
`exposes/startup/resolved` Atlas relation inside the repository scope. The
backend publishes one closed action per eligible relation. The request contains
only request-local refs, bounded semantic labels and representative evidence;
canonical IDs, raw source signals, candidate-file indexes, file trees and raw
internal edges stay local.

The response may select exactly one advertised action and explain the choice
using only request-local refs. Unknown, duplicate, wrong-kind, cross-request or
raw canonical refs fail closed. There is no retry, fuzzy repair, fallback to
the old Orientation request, or automatic second question.

The ordinary run persists a versioned Navigator request/result/status artifact
under the existing confined artifact writer and manifest authority. Debug
exchange recording remains the only Q/A journal. The report projects a small
Navigator recommendation that points at the same Atlas entity/relation IDs and
source evidence already used by the Atlas shelf.

Old Architecture, Guided Tour and Study products consume semantic fields that
the Navigator does not produce. They are not called or fabricated in the first
Atlas-first run. Their UI regions use an explicit localized `not available for
this Atlas-first run` state. Existing provider-free replay/dev paths may remain
temporarily for fixture verification, but ordinary product execution has no
legacy/raw-signal branch and no old response reader.

### Cache correctness

Every reusable semantic cache identity binds the exact provider request plus a
safe provider identity: normalized endpoint digest, model, output language,
prompt/schema contract and effective `max_tokens`. Raw endpoint/auth values are
never persisted. Changing provider identity produces a miss; no migration or
legacy cache reader is added.

Only a locally accepted semantic response is cacheable. Malformed, rejected,
resource-exhausted, canceled, fallback or locally synthesized Architecture
content is never written as a successful provider response. Invalid existing
entries are evicted before one fresh call and never become report authority.

### Honest repository completeness

The local collectors receive the ordinary run context; canceling a run cancels
`git`/`go` subprocesses. The first checkpoint preserves tracked-module ownership
and keeps `GOWORK=off`. Changing workspace semantics is deferred until a dedicated
repository-owned workspace fixture proves the intended behavior; an unrelated
external workspace must never enter repository authority.

Default local package and edge extraction does not discard facts after paying
the full `go list` cost. If an explicit debug/test bound is used, the saved
facts and report carry a closed `partial` completeness record with total,
retained and omitted counts. Module ordering cannot let an earlier module
silently consume the entire shared result. `go list` `Incomplete`, `Error` and
`DepsErrors` become typed warnings/completeness state rather than successful
absence.

These local facts are not copied wholesale into the Navigator request. The
task-shaped compiler remains the only model-visible boundary.

### Presentation compatibility and command output

The superseded whole-report localization stage is not called by the new
Atlas-first ordinary run. While its existing replay/product path remains in the
tree, a response must still contain requested batch indices `0..N-1` exactly
once and in order. Trailing tuples are ignored only when every index is `>=N`;
one closed warning reports the discarded count. Missing, duplicated, reordered,
negative or in-namespace trailing indices, unsafe content and projection/apply
failures remain rejected. There is no resend or fuzzy repair.

Human stderr output is a compact run narrative, not a stream of repeated
`repomap:` prefixes. The run/debug artifact directory appears near the start;
repeated stage facts are grouped under one heading; and `WARN`/`ERROR`, rejected
counts and failed states occupy their own visible lines. Machine stdout and
artifact contracts remain unchanged. This uses one small formatter rather than
a new logging framework.

## Checkpoints and ownership

The work lands as independently reviewable checkpoints under one decision:

1. **Cache gate** — provider identity and accepted-only Architecture cache,
   with provider-free cold/warm/rejected/resource tests.
2. **Completeness gate** — context propagation and non-silent multi-module facts,
   with small multi-module fixtures; workspace-policy changes remain deferred.
3. **Navigator cutover** — ordinary run request/result artifacts and exact
   terminal behavior; old semantic stages are uncalled.
4. **Workspace gate** — Authority-labelled recommendation and localized honest
   unavailable/empty states using the existing source drawer. Unit and package
   cards do not repeat a generic Authority line; Authority is secondary metadata
   only on claims, relations, the Navigator recommendation and evidence details.
   Product-owned Atlas/Navigator labels use the static EN/RU catalog and do not
   invoke the old whole-report model-prose localization stage.
5. **Product gate** — install one identified candidate binary first; then run
   full checks and exact etcd report/UI/JSON reading while the owner exercises
   Casdoor. Fix any findings, commit/push and install the exact final binary;
   optional live A/B remains last.

Parallel agents own disjoint files. Root reviews every checkpoint and owns
`cmd/repomap` integration, shared report/manifest changes, final commit/push and
PATH installation. No agent launches a live LLM.

## Non-goals

- no model-visible raw graph or complete signal bundle;
- no compatibility mode, legacy reader, migration or hidden fallback;
- no invented Boundary, Resource, Contract, mechanism or runtime reachability;
- no request splitting, automatic continuation, output retry or per-stage
  token knob;
- no provider capability framework or second cache/artifact system; and
- no ABA/frozen-worktree work: the owner explicitly classified that scenario
  as non-actionable for this product.

## Proof

- deterministic, permutation-stable Navigator wire and private typed catalog;
- zero old Orientation/Architecture/Guided/Study provider calls in an ordinary
  Atlas-first provider-free run;
- endpoint/model/language/request/max-token cache isolation and accepted-only
  cache writes;
- cancellation and repository-local multi-module fixtures with explicit
  completeness;
- report/manifest hashes and every clickable Navigator/Atlas item bound to an
  exact saved source excerpt; and
- saved-response Go integration fixtures plus direct built-binary Casdoor and
  etcd runs in fresh artifact roots, full manifest readback, exact pushed SHA
  and installed binary SHA-256.
