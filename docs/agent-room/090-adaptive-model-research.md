# Decision: Adaptive bounded model research

**Status**: Approved for implementation

**Approved by**: Repository owner in the current implementation session

## User-visible goal

Replace the initial orientation bundle as repomap's de facto complete
understanding boundary with a small, purposeful, cached sequence of bounded
provider calls. Deterministic local extraction remains authoritative. A normal
run may use broad orientation, up to two targeted research rounds over locally
selected exact evidence, and final architecture synthesis.

## Approved implementation scope

1. Separate the complete locally authorized repository universe, each bounded
   provider-visible bundle, and each bounded focused investigation scope.
2. Keep full local command traces and exact local evidence available to
   FlowProof even when the initial provider bundle omits their files.
3. Replace the fixed orientation file count as the primary context policy with
   measured request-byte limits plus secondary count ceilings.
4. Hard-cap a normal run at four semantic provider calls and approximately
   256–320 KiB of external request bodies, with at most two targeted rounds.
5. Add a minimal persistent research-round and working-theory contract that
   keeps deterministic facts separate from accepted and rejected model
   interpretations.
6. Select targeted questions and evidence locally. Require new exact evidence,
   a valuable unresolved question, and remaining call/byte budget before each
   targeted call.
7. Validate every targeted finding against supplied opaque evidence IDs. Model
   output may interpret or group supplied evidence but may not create files,
   symbols, surfaces, transitions, proof, runtime order, or evidence.
8. Cache orientation, targeted research, and architecture stages with
   stage-specific fingerprints over repository inputs, scenario, prompt,
   provider/model, exact evidence bundle, and this research policy.
9. Feed accepted evidence-backed research interpretations, saved traces,
   surfaces, anchors, exact member IDs, and unresolved frontiers into final
   conceptual architecture synthesis.
10. Persist typed per-stage cost, cache, evidence, rejection, progress, and
    coverage metrics and expose a compact collapsed Model research detail.
11. Add saved-response Restic and Caddy regressions; automated tests make no
    network calls. Record bounded live fixture measurements when credentials
    are available, without making them a test prerequisite.

## Preserved behavior and authority

- Product entrypoint and UX remain `repomap <repo>`.
- No full repository source dump is sent to a provider.
- Provider path and opaque-ID validation remain fail-closed.
- Local repository authorization, build selection, secret/ignored-file policy,
  exact evidence, surfaces, transitions, traces, and proof remain local facts.
- Browser navigation, zooming, selection, filtering, and evidence opening make
  zero provider calls.
- Existing accepted surface-accounting, architecture, freshness, manifest, and
  investigation behavior remains intact unless this decision explicitly
  changes its model-research boundary.

## Non-goals

Do not add an autonomous agent loop, model-selected arbitrary paths, provider
tool execution, per-click calls, a database, architecture-canvas redesign,
unbounded retries or context, mandatory four-call runs, model-created facts, or
deep analysis of every discovered surface.

## Acceptance

The change is accepted when provider-visible context remains bounded while
local evidence and FlowProof are independent of the initial bundle; up to two
locally gated targeted rounds fit within a hard four-call/total-byte policy;
identical stages replay cached validated results; failed rounds preserve local
evidence and prior findings; accumulated grounded research informs architecture
synthesis; typed report metrics explain scope, cost, cache, and stop reasons;
and Restic/Caddy saved-response regressions demonstrate improvement without
invented facts or networked tests.
