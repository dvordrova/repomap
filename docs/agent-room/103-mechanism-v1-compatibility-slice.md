# Decision: Mechanism v1 compatibility slice

**Status**: Approved for implementation

**Approved by**: Repository owner through the accepted repository knowledge
object investigation in the current implementation session

## Product question

Can the accepted Caddy directory-listing artifact become one durable,
question-centered Mechanism object with stable local identity, per-object
inputs, scoped replay, and reuse by Start Here, Search, and the existing map,
without another model call, repository analysis, or renderer?

## Approved implementation

1. Add one concrete versioned `semanticdiscovery.Mechanism` payload. Do not add
   a generic knowledge-object interface, registry, relation ontology, or a
   second semantic pipeline.
2. Reuse the accepted candidate, leaf observations, fan-in proposal, Fact
   contract, claim lineage, existing validators, and Artifact materializer.
3. Give the accepted Caddy mechanism an owner-assigned identity:
   repository `github.com/caddyserver/caddy/v2`, intent key
   `caddy-directory-listing`, and Go-package scope
   `github.com/caddyserver/caddy/v2/modules/caddyhttp/fileserver`.
4. Bind only the candidate-scoped compatibility input: its six original seed
   facts, seven Golden enrichment facts, typed intent/capability contract, and
   exact saved bounded-probe digest. Planner context, Guided Tour prose,
   unrelated facts, whole-bundle hashes, and repository HEAD are excluded.
5. Hash fact truth without report-derived Focus. Evidence paths and locations,
   claims, bases, support, coverage, gaps, contract versions, and the explicit
   editorial ordering basis remain bound.
6. Replay through the current opportunity, leaf, fan-in, and materialization
   validators, then project back into the existing `Artifact`. The projection
   must equal the accepted Caddy artifact on the original fixture.
   The legacy global semantic `Record` is an extraction source only; saved
   Mechanism replay must not require it.
7. Merge the projection into `ReportData.SemanticArtifacts` before Search. Add
   only a presentation pointer selecting it for Start Here; reuse the existing
   semantic-artifact canvas narrative and evidence inspector.
8. Missing or stale Mechanism data degrades to the existing report. It must not
   remove other semantic artifacts or break report generation.

## Focused checks

- logical identity survives editorial title/order changes;
- Planner Context, Guided Tour prose, unbound facts, repository HEAD, and
  report-derived Focus do not stale replay;
- a missing or changed bound fact, probe digest, capability/aspect contract,
  claim, lineage, or gap is rejected;
- strict JSON and content-hash validation reject malformed records;
- accepted Caddy projection retains its existing artifact hash and appears in
  Start Here, Search, map steps, and evidence;
- exact repository namespace and Go-package scope resolve in the current saved
  repository graph;
- no model, package loading, SSA, call graph, or runtime-surface discovery runs.

## Hard exclusions

- no migration of other semantic kinds;
- no DependencyUsage payload yet;
- no candidate-free seven-fact schema in this slice;
- no new universal renderer or Guided Story conversion;
- no new repository analyzer or model call;
- no broad runtime-surface performance work.

## Stop condition

Stop if exact compatibility requires changing the accepted claims, weakening a
validator, migrating every Artifact kind, or adding a parallel truth pipeline.
