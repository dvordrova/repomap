# Verdict: the night run of 2026-09-03

Judged the way the owner said it would be judged: by opening a report.

## Are the anchors real

Every anchor on all three pages was checked against its repository at the
captured revision: 127 rendered as text and 531 member chips, 658 in total,
each naming a file that exists and a line inside it. None missing. The
acceptance fixture now carries that as a test, so it stays true.

## What a reader gets

Both reports answer all seven acceptance questions without leaving the page.
The one that could not before was "on which port": the fixture's answer was
buried in a target's configuration table and chi's did not exist, because a Go
program that hard-codes its address had no fact for it.

The page is one self-contained HTML: one inline `<style>`, one inline
`<script>`, no external script, stylesheet, font or image. The only remote
references are the GitHub permalinks the anchors point at. It can be dropped
in a bucket as it is.

## What changed on the page

Every target page opens with a map of that target's groups, laid out left to
right as what reaches in, what the target is, and what it reaches out to, with
a bar for how many symbols each group holds, a curve per connection, and the
main-flow step numbers on the groups the flow passes through. It is plain SVG
laid out in Go: with scripting off every node is still a link to the group it
names, and scripting only adds a neighbourhood preview that dims and a click
that marks the group it landed on. Neither moves anything.

The overview leads with the model's summary instead of four blocks of README
text, and the quotes moved to the end, clamped to three lines. The main flow
is a numbered sequence rather than a fifth plain list. The target bar sticks
and each target carries a bar of its own sections with counts, so a reader can
see what is behind a link before following it.

## What changed underneath, and what it cost

The report used to differ between two runs of the same repository because the
run id sat inside the facts digest, so the orientation stage never hit its
cache and paid for a live call every time. Two runs now produce the same
bytes.

Three things were printing something untrue or nothing at all:

- a key repeated with an identical value discarded whole answers, which cost
  one target twelve groups and twenty connections in a single run;
- mounted route prefixes did not compose, so chi's article list read `GET /`;
- the grouping prompt had no size rule, and for one unchanged repository the
  model returned between four and thirteen groups, with the four-group answers
  putting two thirds of the target in one box.

The last one is the one to watch. Every model stage is a coin flip until it is
cached, so a single cold run proves nothing about quality. The rule now asks
for one responsibility a reader would name out loud, eight to fifteen of them,
and no group over a fifth of what it was given. Across four cold draws after
the change: 8, 10, 13 and 9 groups, largest at 4% every time.

## What is not done

- `os.environ["KEY"]` and `process.env.KEY` subscript reads are still not
  captured, and a numeric listen port as JavaScript writes it is not either.
- `~/git/fuego` fails before analysis on incomplete `go list` authority.
- Three repositories were read end to end. Two more were tried and are
  recorded rather than fixed: beets is far past medium (26,218 objects, about
  820 categorization requests) and was stopped, and fuego fails before
  analysis on incomplete `go list` authority.
- python-dotenv took 864 s cold against chi's 111 s for a repository a
  quarter the size, because it is three targets and each one carries the whole
  test tree. Its groups are named after tests as often as after the library.
  Whether a target should include its own tests is a product question nobody
  has answered.
