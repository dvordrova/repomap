# Decision: Fresh Repo Demo v2.4

Status: Approved by the repository owner in the current implementation
session.

## Product outcome

The ordinary `repomap` command analyzes the current repository, automatically
selects and investigates at most three bounded central mechanism questions,
publishes any locally validated Mechanism v1 through the existing report path,
serves the report on localhost, and opens `#/overview`.

The fixed cold product target for this experiment is the untouched public
`benbjohnson/litestream` checkout. No Litestream-specific source code, prompt,
validator, candidate, seed, intent key, or presentation rule may be added.

## Approved implementation scope

1. Reuse the existing deterministic repository snapshot, compact orientation,
   saved research windows, semantic opportunity contract, bounded syntax probe,
   local reducers, Mechanism v1, report, Search, and report server.
2. Propose at most five model-written questions from existing bounded facts,
   select at most three locally, and freeze each selected question, intent,
   scope, aspects, capabilities, probe budget, and acceptance rubric before
   synthesis.
3. For each selected candidate, inspect at most eight files, fifteen functions,
   three local expansion levels, 128 KiB retained source, five seconds of probe
   time, and two exact named frontier follow-ups.
4. Perform at most one semantic synthesis call per selected candidate. A
   semantic validation rejection is final for that candidate; transport retries
   remain governed by the existing provider policy.
5. Derive acceptance and verdict locally. Model prose cannot create paths,
   symbols, facts, evidence, semantic IDs, confidence, or canonical authority.
6. Publish accepted results as the existing Mechanism v1 and semantic Artifact;
   failed candidates remain supervisor-only. If none is accepted, retain the
   existing code-first no-Mechanism fallback.
7. Disable repository-wide runtime-surface discovery by default for the normal
   product command. Keep it explicitly opt-in through the existing flag.
8. Preserve `--no-open`, `--no-search`, and `--no-serve`; the default run serves
   on `127.0.0.1`, prints the exact URL, and opens Overview.
9. Add one presentation-only source projection improvement: when a visible
   accepted step contains multiple substantial supported operations, show
   compact exact fragments covering those operations instead of only one
   dominant cluster. Preserve all evidence and semantic identity.
10. Save the cold run, runtime accounting, honest acceptance/rejection results,
    review instructions, and screenshots under the untracked
    `tmp/fresh-repo-demo-v24/` directory.

## Explicit non-goals

- No global SSA, call graph, pointer analysis, runtime-surface discovery, or
  repository-wide lifecycle/flow analysis.
- No changes to semantic truth contracts, validators, Search ranking,
  architecture canvas, Mechanism v1 identity, or User Report behavior beyond
  multi-fragment source completeness.
- No cache redesign, second model, retry after semantic rejection, UI polish,
  DependencyUsage, MCP, or repository-specific recovery patch.

## Acceptance

The experiment succeeds only when the untouched Litestream run publishes at
least one source-backed Mechanism with three or more meaningful visible steps,
zero unsupported user-visible claims, and a human score of at least 3/4. A
negative cold result is preserved honestly rather than repaired with target-
specific intervention.
